# 346216_01.cpp: 計算規模を確認する試行版

[346216_01.cpp](346216_01.cpp) は、初期値1,2のUlam数を順番に計算し、10の整数乗番目の項を標準出力へ出す。C++17のソース1本でビルドできる。C++17、128 bit整数を扱えるコンパイラ、64 bitのPOSIX環境が必要で、macOSのApple Clang 16で確認した。

b-fileを含む `.txt` は公開セットに同梱しない。01の計算と検査は、入力用のb-fileを必要としない。

検索範囲や圧縮辞書が不足すると、確定できない候補の判定前にエラーで停止する。必要な全探索や辞書外保存を自動で補う版は [346216_02.cpp](346216_02.cpp)。その実行方法、剰余による検索の理由、参考文献は [README.md](README.md) にある。

## ビルドと実行

以下は、このREADMEがあるディレクトリをカレントディレクトリとして実行する。

```sh
/usr/bin/xcrun --sdk macosx clang++ -std=c++17 -O3 -Wall -Wextra -Wconversion -Wshadow 346216_01.cpp -o ulam_probe
```

小規模な計算と独立オラクルによる比較:

```sh
./ulam_probe --terms 10000 --verify-until 120000 --report 0
python3 verify_probe.py
```

検査スクリプトにはPython 3と標準ライブラリを使う。Pythonは通常の計算には不要。引数を省略すると、目標100万項、時間上限60秒、RAMの所属表、候補値上限は目標項数の14倍となる。

100億項を計算する場合の実行例:

```sh
./ulam_probe --terms 10000000000 --seconds 86400 --disk cache_346216_01.bin --cache-mib 8 --report 10000000 > a10_01.csv
```

時間上限は24時間。01の `--seconds` は1から86,400までで、02と異なり0による時間制限の解除はできない。時間確認は候補65,536個ごとのため、指定秒数は厳密な締め切りではない。`--disk` は存在しない新しいファイル名を指定し、既存の作業表を上書きしない。作業表の初期容量は、この設定では約7.78 GBの論理サイズになる。

## 出力と保存

標準出力のCSVは、次の形式である。

```csv
index,value
10,18
100,690
1000,12294
```

`index` はUlam数の項番号であり、A346216の添字ではない。100億項目は `10000000000,135174535215` の行になる。目標が10の整数乗でない場合は、完了時に目標の項も出力する。通常は10項目から出力する。目標を2項にした場合は、完了時に `2,2` を出力する。

進捗と正常終了時のJSONは標準エラーへ出る。`percent` は目標項数に対する進捗率、`eta_seconds` は開始からの平均速度による残り時間の予測。最後のJSONの `status` が `complete`、`terms` が指定した目標項数、終了コードが0なら、計算の目標に到達した。検出したエラーでは終了コード1となり、標準エラーに `status=incomplete` と理由を出す。

01はb-fileや終了JSONを別ファイルへ自動保存しない。上のリダイレクトで保存するのはCSVだけであり、進捗と終了記録は端末に出る。CSVの行ごとの `fsync` や標準出力の書き込み失敗検査もないため、正常終了の表示だけでCSVの永続保存まで確認したことにはならない。保存されたCSVを別途確認する。

作業表の `.bin` は18 bitごとの所属情報を符号化した計算用データ。復号辞書、最近の項、検索木などはRAMにあり、作業表だけから途中再開できない。途中までのCSVもチェックポイントではない。

## 停止条件と正確性の範囲

経験的な剰余分布で候補そのものを除外しない。低い側・高い側の検索木は、各 `cutoff` 未満のキーの項を全て保持する。2組が見つからず、必要な検索範囲が保存範囲に達する場合は `omitted anchors` として停止する。最近の項だけで判定が終わらず、窓が不足する場合も `window exhausted` として停止する。

所属表は18 bitパターンを最大256種類の辞書で保存し、257種類目が出れば停止する。このほか、検索木ごとの50万項の上限、候補値の上限、時間上限、検出した資源不足やI/O失敗でも非完了として停止する。既定の候補値上限が目標項数の14倍で足りることは、全範囲で証明された密度評価ではない。

01は未確定の候補を推測して継続する機能を持たない。これらの停止条件を自動で補う02とは、完了できる範囲と保存機能が異なる。C++実装全体の形式検証や、100億項全体の別方式による独立検算は行っていない。

## 計算・検査記録

ユーザーの実行で保存された [results/a10_01.csv](results/a10_01.csv) には、10項目から100億項目までの節目がある。10億・100億項目の値は02の [a9_summary.json](results/a9_summary.json)・[a10_summary.json](results/a10_summary.json) と一致する。この01の実行については、終了JSONや所要時間の保存記録はない。

[verify_probe.py](verify_probe.py) は候補3から120,000までの各判定を独立した組和列挙と比較する。3種類の整数比、RAMとSSDの一致、4 GiB超の位置、既存ファイル保護、資源上限と正確に停止する条件、進捗表示も検査する。通常版とUBSan・bounds検査・libc++のextensive hardening付きの版で実行した記録は [publication_checks.json](results/verification/publication_checks.json) にある。

検査付きのビルドと実行:

```sh
/usr/bin/xcrun --sdk macosx clang++ -std=c++17 -O1 -g -Wall -Wextra -Wconversion -Wshadow -fsanitize=undefined,bounds -fno-sanitize-recover=all -D_LIBCPP_HARDENING_MODE=_LIBCPP_HARDENING_MODE_EXTENSIVE 346216_01.cpp -o ulam_probe_ubsan
python3 verify_probe.py ./ulam_probe_ubsan
```

ASanはこの環境の最小プログラムでも初期化に失敗したため、ASan検査を通過したとは扱わない。実行ファイル、作業表、デバッグ情報は公開セットに含めない。
