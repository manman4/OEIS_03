```math
N = 896315812331399
```

この反例は OEIS Open project で発見され、Tom Adamczewski が報告した。本フォルダには、C版・C++版の検証器と、それぞれの実行結果を収録する。

## 検証方法と網羅性

定義の変数を次のように置き換える。

```math
W=w+2,\quad X=x+3,\quad Y=y+5,\quad Z=z+7
```

したがって、調べる式と変数の範囲は次のとおり。

```math
N=\binom{W}{2}+\binom{X}{4}+\binom{Y}{6}+\binom{Z}{8},\quad W\ge2,\quad X\ge3,\quad Y\ge5,\quad Z\ge7
```

各項は非負なので、どの項も対象の整数以下である。最初の三角数の項は1から、残りの項は0から始まり、いずれも狭義単調増加する。このため、二項係数が対象の整数を超えたところで打ち切っても解を失わない。対象の反例における個別の上限は次のとおり。

| 定義の変数 | 範囲（両端を含む） | 置き換え後の上限 |
| --- | --- | --- |
| w | 0〜42,339,479 | 42,339,481 |
| x | 0〜12,109 | 12,112 |
| y | 0〜927 | 932 |
| z | 0〜274 | 281 |

検証器は各項の値を生成し、Z、Y、X の順に列挙する。三つの項の和が対象の整数以上なら、最初の項が正でなければならないことと単調性から、それ以降を打ち切る。残差については次の同値条件を使う。

```math
r=N-\binom{X}{4}-\binom{Y}{6}-\binom{Z}{8}\ge1,\quad (\exists W\ge2,\ r=\binom{W}{2})\iff 8r+1\text{ が平方数}
```

実際、右向きは次の恒等式による。

```math
8\binom{W}{2}+1=(2W-1)^2
```

逆向きでは、正の残差の8倍に1を足した数の平方根は3以上の奇数であり、次の値が一意に定まる。

```math
W=(\sqrt{8r+1}+1)/2\ge2
```

C++版の平方数判定では、4095を法とする平方剰余に入らない候補だけを除外し、残りは整数平方根と整数の積で判定する。平方数を法で割った余りは必ず平方剰余なので、この除外で解を失うことはない。C++版の平方根の計算は整数 Newton 法で、浮動小数点演算を使わない。

整数平方根では、平方根以上の2の冪から始める。現在値が整数平方根より大きい間は、Newton 更新後の整数も整数平方根以上で、現在値より小さくなる。更新で減少しなくなった時点の値が整数平方根である。

入力は0以上10の15乗以下に制限している。残差の8倍に1を足した値と、その整数平方根の2乗は64ビット符号なし整数の範囲に入る。二項係数の生成時には乗算を128ビットで行い、各段階の割り算は二項係数の漸化式によって割り切れる。入力上限を超える最初の二項係数までしか生成しないため、その中間積も128ビットの範囲に入る。

C版も同じ有限範囲を列挙し、正の三角数かを判定する。`sqrtl` で平方根の初期値を求め、128ビット整数の積で上下に補正してから完全平方かを判定する。浮動小数点の丸めに最終判定を任せない。残差の8倍に1を足す計算と、補正中の平方計算も128ビットで行う。C版には平方剰余による除外処理はない。

C版のテーブルは各項が対象の整数以上になった時点で打ち切る。最初の三角数の項が1以上なので、残りのどれかの項が対象の整数以上になる解はなく、この打ち切りで解を失わない。

C版では表現数と入力値に64ビット符号なし整数を用いる。入力は数字だけの十進表記とし、全引数の形式と上限を計算開始前に確認する。メモリの確保・拡張に失敗した場合と、標準出力への書き込みに失敗した場合は、標準エラーへ診断を出して異常終了する。

## 実行

以下のコマンドは、この README があるディレクトリをカレントディレクトリとして実行する。確認したコンパイラは Apple Clang 16.0.0（arm64）。両方とも GCC/Clang の128ビット整数拡張を使用する。Python は通常の計算には不要。

### C版

C11 と標準数学ライブラリを使用する。`-lm` は数学ライブラリを明示的にリンクするために付ける。

```sh
cc -std=c11 -O2 -Wall -Wextra -Wconversion -Wshadow -pedantic a306477.c -lm -o a306477
./a306477 896315812331398 896315812331399 896315812331400 > c_result.out
```

上の計算は3入力の探索がすべて完了すると終了する。同梱の [c_result.out](c_result.out) に記録した標準出力は次のとおり。

```text
a(896315812331398) = 89
a(896315812331399) = 0
a(896315812331400) = 67
```

引数なしの `./a306477` では、1〜80の表現数、23343989の表現数、反例の表現数を順に出力する。引数に整数を指定すると、それぞれの表現数を計算する。符号、空白、数字以外の文字、上限超過の入力は受け付けない。

### C++版

C++20 を使用する。

```sh
clang++ -std=c++20 -O3 -Wall -Wextra -Wconversion -Wshadow -pedantic verify.cpp -o verify
./verify 896315812331398 896315812331399 896315812331400 > result.out 2> progress.log
```

結果と表現例は標準出力、改行区切りの進捗は標準エラーに出す。計算の途中結果から不存在を判断せず、正常終了後の `result` 行を確認する。

各版のコマンドは、同梱の `c_result.out` または `result.out` を新しい実行結果で上書きする。元の記録を残す場合は出力先を別の名前にする。所要時間は実行環境によって異なる。

公開・移動するファイルは上記の一覧の7ファイルで足りる。実行ファイル、デバッグ情報、進捗ログ、macOS のテキストクリッピングは `.gitignore` で除外している。二つの結果ファイルは明示的に公開対象としている。

### C版の回帰テスト

Python 3 の標準ライブラリと C コンパイラを使用する。テスト用の実行ファイルは一時ディレクトリに作成する。

```sh
python3 test_a306477.py
python3 test_a306477.py --ubsan
```

0〜30の定義による直接全探索、入力の拒否、入力上限の受理、64ビットの境界付近の三角数判定、メモリ確保失敗時と標準出力への書き込み失敗時の異常終了を検査する。`--ubsan` は未定義動作検出を有効にする。コンパイラは環境変数 `CC` で指定できる。検証器本体の入力上限は10の15乗であり、64ビット全域のテストは内部の三角数判定関数に対して行う。

## 結果と確認範囲

| 対象の整数 | C版の表現数 | C++版の表現数 | C++版で判定した三変数の組数 |
| --- | ---: | ---: | ---: |
| 896315812331398 | 89 | 89 | 2,755,643,831 |
| 896315812331399 | 0 | 0 | 2,755,643,831 |
| 896315812331400 | 67 | 67 | 2,755,643,831 |

両版とも三つの入力すべてについて探索が正常終了し、表現数が一致した。対象の各整数に対して可能な変数の範囲をすべて調べた。C版の出力は [c_result.out](c_result.out)、C++版の全表現・三変数の組数・所要時間は [result.out](result.out) に記録している。

- C版では、1〜80の表現数が定義による直接全探索と一致し、23343989の表現数が1になることも確認した。
- C版の回帰テストは通常実行・UBSan付き実行とも成功した。0〜30の直接全探索との照合、1,022入力の三角数判定、不正入力と上限の検査、メモリ確保・標準出力の失敗時の異常終了を確認した。
- 上記の発見報告にある Python 検証コードも実行し、対象の整数に表現がなく、前後の整数には表現があることが一致した。
- 0〜50について、定義の4変数をそれぞれ0〜50とする51の4乗個の組の直接列挙と、C++ 検証器の表現数がすべて一致した。この上限で十分なのは、定義の各二項係数が対応する非負変数以上だからである。
- 前後の整数に対して出力した計156個の表現を、Python の `math.comb` で再計算して一致を確認した。
- 整数平方根は、平方数付近・2の冪付近・乱数を含む11,195入力で、Python の `math.isqrt` と一致した。この検査と0〜50の検証器実行では、UBSan の診断はなかった。

これは対象の整数に表現がないことの計算検証であり、これより小さいすべての正整数を調べたものではない。最小の反例であるかどうか、および Lean 証明の再コンパイルは今回の確認範囲に含まない。
